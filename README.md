`examType` 값은 `실제기출` · `모의고사` · `창작문제` 셋입니다. 목록 상단의 `구분` 필터로 나눠 볼 수 있습니다.

> 위 표의 수치는 본문을 직접 확인한 값이므로 플래그를 세어 나온 값과 다릅니다 — 플래그를 믿지 마세요.

**창작문제** — 기출이 아닌 사례집 신작 문제입니다. 현재는 민사법의 정연석 「로스쿨 사례의 정석」
(로사정, 26.02) 163사례가 유일하고, 기출과 **같은 스키마**로 들어가 문제 풀기·모범답안·AI 채점이
그대로 동작합니다. 다른 점은 공식 채점기준표가 없다는 것뿐이며, 채점 근거는 최고답안과 각주가
대신합니다. 원본 PDF의 OCR 오인식(당사자 기호 `乙`이 **전량** `江`·`己`로 깨져 있었음)은
전부 지면과 1:1 대조해 교정했습니다 — 아래 "로사정 파이프라인" 참고.

- 변호사시험은 공식 채점기준표가 공개되지 않아, 사례집 모범답안이 유일한 채점 근거입니다.
- 기출 55건 기준으로, 공법은 55건 전부, 형사법은 50건(변시 1~5회 제외), 민사법은 48건(변시 1,2,3,5,9,12,14회 제외) 채점 근거를 확보했습니다.
  - 형사법 변시 1~5회는 사례집(조균석, 형사법 사례형 해설)이 QR코드 온라인 제공으로 전환되어 텍스트 추출 대상에서 빠졌습니다.
  - 민사법 변시 1,2,3,5,9,12,14회는 사례집(정연석, 로스쿨 민사 사례형 기출문제집[해설편])에 해당 회차의 상세 해설이 없고 "요약"만 있어(책 서두에 명시) 채점 근거로 쓸 만한 텍스트를 뽑지 못했습니다.
  - 위 회차들은 문제 지문은 있지만 채점 근거가 없습니다.
- 앱 상단에서 과목을 전환할 수 있습니다(`localStorage`에 마지막 선택 과목 기억).

## 쟁점별 풀기 — 사례집 목차 모드

"쟁점별로 풀기" 안에 두 하위 모드가 있습니다.

- **사례집 목차로 풀기** — 사례집의 실제 목차(편 → 사례 순서)를 그대로 따라가며, 각 사례를 클릭하면 해당 문항으로 바로 이동합니다. 목차 데이터(`casebook_toc.json`)가 없는 과목은 이 모드에서 "사례집 목차 데이터가 없습니다"만 뜨고 안전하게 아무 동작도 하지 않습니다.
- **쟁점 검색** — 쟁점 태그를 검색해서 그 쟁점이 나온 지문 전체를 봅니다. 목차 데이터 유무와 무관하게 항상 동작합니다.

공법은 강성민 헌법·행정법 사례형 연습 교재를 기준으로 목차 모드가 구축되어 있습니다. 목차 데이터는 사례집 PDF를 OCR 텍스트로 추출한 뒤 정규식으로 파싱·매칭한 것이라 완벽하지 않습니다. 헌법·행정법 각 142개 사례 중 약 93~94%가 시험(연도/회차)까지 매칭되고, 그중 대부분은 문항(그룹)까지 매칭됩니다. 매칭 안 된 항목은 "미연결"로 표시되고 클릭해도 아무 동작이 없습니다 — 주로 2013년 이전 모의고사(데이터 범위 밖)이거나 OCR 오인식 때문입니다. 문항 단위는 매칭됐지만 그 문항이 여러 설문으로 이뤄진 경우, 그 설문 전체가 아니라 casebook이 가리키는 특정 설문이 아닐 수 있습니다(문항 내부 세부 설문 단위 하이라이트는 아직 지원하지 않음).

형사법은 처음에 확보했던 사례집(조균석, 형사법 사례형 해설)이 시험 회차 순으로만 구성되어 "편 > 주제별 사례" 구조가 없어 보류했다가, 주제별 목차를 가진 책 3권(이인규 형법 변사기 · 이창현 사례형사소송법 · 작은변사기 형사소송법)을 추가로 넣어 목차 모드를 만들었습니다. 이창현·작은변사기는 창작 사례가 많아 실제 시험과 매칭되지 않는 항목이 상당수 "미연결"로 남습니다.

민사법도 같은 이유로 보류했다가 4권(인사이트 상법 · 송영곤 민소사연 · 박승수 CBT실전답안 · 정연석 로사정)으로 목차 모드를 만들었습니다. 이 중 **로사정 163사례는 앱 안에 창작문제로도 들어가 있어**, 목차에서 사례를 클릭하면 그 사례가 시험 화면으로 바로 열립니다 — 다른 사례집처럼 "기출의 어느 문항인가"를 매칭할 필요가 없는 유일한 경우입니다.

## 문제 화면 서식

### 레이아웃 — 좌우 2단

실제 시험 CBT 화면(문제-답안 분리)을 참고해 왼쪽에 문제(시험 정보·문항 탭·설문 목록·지문), 오른쪽에 답안 작성(텍스트 입력·제출·모범답안)을 나란히 배치합니다. 각 열은 독립적으로 스크롤되어(`overflow-y:auto`, `max-height:calc(100vh - 90px)`) 답안을 쓰면서 지문을 오르내리며 다시 스크롤할 필요가 없습니다. 창 너비가 860px 미만이면(모바일 등) 자동으로 위/아래 1단으로 접힙니다.

지문(사실관계)은 박스 처리, 설문(문제)은 굵게, 참조조문은 더 작은 글씨 + 점선 구분선으로 시각적으로 나눕니다. `splitProblemText()`가 원문에서 "<문제>"·"[참조조문]" 같은 표지, 또는 표지가 없으면 번호매김 문단 경계(`1.`, `(1)` 등)를 찾아 블록으로 나눕니다. 형사법처럼 지문보다 앞서 법조문 전문이 나오는 문서는 맨 앞의 법조문 문단들을 먼저 조문 블록으로 떼어냅니다. `[참조 조문]` 표지 뒤에 표지 없이 곧바로 다음 사례의 지문이 이어붙는 경우도 있어, 조문처럼 보이는 문단(`제N조(`, `「…」`, `※`, `[별표]`로 시작)이 이어지는 동안만 조문으로 처리하고 그 뒤는 다시 지문으로 되돌립니다. 표지·번호 매김이 없는 극소수 문항(설문이 사실관계 문장에 그대로 이어붙는 경우)은 구조적으로 감지가 안 되어 지문 박스에 그대로 남습니다.

### 문항 번호(제1문 / 제1문의1 등)

변호사시험·모의고사 사례형은 배점이 문항(제N문)당 정확히 100점이고, 한 문 안에 사실관계가 여럿이면 "의1, 의2, …"로 나뉩니다(예: 15회 공법 — 제1문의1~3이 각 35/35/30=100점, 제2문이 100점). `data/*/exams/*.json`의 문항 그룹은 이 규칙(배점을 순서대로 누적하다 100점에서 문항을 닫음)으로 자동 재라벨링되어 있어, 페이지 탭·페이지 제목은 **모든 시험에서 항상** 실제 표기(`제1문`, `제1문의2` 등)를 보여줍니다.

문제 지문 안에도 각 사례가 시작하는 자리에 `〈제1문의2〉` 같은 라벨을 끼워 넣지만, 이건 지문 텍스트에서 사례 경계를 다시 찾아 문항 그룹 수와 정확히 일치할 때만 표시합니다(일부 시험은 문항 그룹 하나가 실제로는 사례 하나 속 세부 설문 그룹일 뿐이라 그룹 수와 지문상 사례 경계 수가 다름 — 이럴 땐 틀린 라벨을 붙이느니 아예 안 붙입니다). 현재 지문 내 라벨까지 정확히 표시되는 시험은 공법 11/55·형사법 22/55 정도이고, 나머지는 페이지 탭 라벨만 정확합니다.

**민사법은 배점 총합이 200점이 아니라 350점**이라 위 "100점당 한 문" 규칙이 그대로 들어맞지 않습니다(공법·형사법 15회 PDF로 검증된 규칙과 달리, 민사법은 실제 PDF로 검증하지 못함). 그래도 배점 누적이 100을 넘는 지점마다 문항을 닫는 동일한 로직을 적용해 대략 제1문~제4문으로 묶었고, 이는 원래 태깅 데이터가 애초에 "문제 구분 없이 설문 1~21번" 같은 평평한 번호만 갖고 있던 것(그대로 뒀다면 21개의 낱개 페이지가 됨)보다는 낫지만, 문 사이 경계가 정확히 어디인지는 검증되지 않았습니다. 지문 내 라벨도 안전장치상 표시되지 않습니다.

## 통합 규격

### 쟁점 ID — 4체계를 잇는 축

암기장·선택형·사례형·기록형이 같은 ID로 같은 논점을 지칭합니다.

```
PUB-0001  재판의전제성      path: ["공법","헌법"]
PUB-0003  협의의소익        path: ["공법","행정법"]
```

- **목차 위치를 ID에 넣지 않습니다.** 기본서 개정·목차 재편으로 태깅이 무효화되는 것을 막기 위함
- ID는 한 번 부여하면 재사용하지 않습니다
- 계층은 `path` 필드로 별도 관리
- 표기 흔들림(`비례원칙`↔`과잉금지원칙`)은 `aliases`로 통합

과목별 접두사: `PUB`(공법) · `CIV`(민사법) · `CRI`(형사법) · `INT`(국제법) · `ITL`(국제거래법)

### store.js — 이 API 표면은 바꾸지 않습니다

앱 4개가 의존하므로, 내부 구현(IndexedDB → Firestore)을 갈아끼워도 호출부는 그대로입니다.

```js
Store.init({ remoteUrl })          // remoteUrl 생략 시 로컬 전용
Store.setUser(uid) / getUser()
Store.record(result)               // 학습 결과 1건 (선택형·사례형 공용)
Store.getRecords(filter)
Store.getMastery(subject)          // 쟁점별 숙달도 집계 ← 연동 지점
Store.getProgress(subject, round) / setProgress(...)
Store.getDraft(key) / setDraft(key, text) / clearDraft(key)
Store.sync(subject)
```

`record()`에 넘기는 형태:

```js
{ subject, mode:'mcq'|'case'|'record'|'memo',
  examId, label, round, issueIds:[], text, seconds,
  correct, score, maxScore }
```

### 앱 간 이동

```
암기장 → 사례형   /CASE_Practice/?issue=PUB-0001
사례형 → 암기장   /Core_Notes/#PUB-0001
노션  → 사례형   /CASE_Practice/?exam=민사법_로사정_003_사례
노션  → 사례형   /CASE_Practice/?exam=민사법_변시_15회_사례&group=문5
```

- `?issue=` — 해당 쟁점으로 자동 필터링합니다.
- `?exam=` — 그 시험을 바로 풀기 화면으로 엽니다. **과목은 id 앞부분(`민사법_…`)에서 읽으므로**
  마지막에 보던 과목이 무엇이든 링크 하나로 정확히 열립니다. id에 한글이 들어가지만 URL에 그대로
  써도 됩니다(브라우저가 인코딩합니다).
- `&group=` — 그 시험의 특정 문항으로 바로 넘어갑니다. 그 시험에 **실제로 있는 문항일 때만**
  적용하고, 없는 값이면 조용히 무시하고 첫 문항을 엽니다 — 엉뚱한 문항을 여느니 처음부터
  보는 편이 낫기 때문입니다. 문항 키는 `index.json`의 `exams[].groups[].key`입니다.

노션 「로민정 단원」 DB의 CASE 섹션 61단원에 이 `?exam=` 링크 183줄이 걸려 있습니다.
대응표(어느 단원에 어느 사례를 걸었는지, 그리고 그 근거)는 노션이 아니라
[`pipeline/scripts/link_romin_case.py`](pipeline/scripts/link_romin_case.py)의 `MAP`에 있습니다 —
노션은 판본 관리가 안 되기 때문입니다.

기출(변시 15 + 모의 40)은 한 시험에 논점이 여럿 섞여 있어 `?exam=`만으로는 단원 링크로 쓸 수
없습니다. `&group=`이 그래서 필요했고, 이제 기출도 문항 단위로 걸 수 있습니다.

### 프라이버시

답안 전문은 **기기 안(IndexedDB)에만** 저장됩니다.
원격에는 점수·소요시간·쟁점 ID 같은 요약만 전송합니다.

## 로사정 파이프라인

민사법 창작문제 163건은 다른 데이터와 달리 PDF 1권에서 통째로 뽑아낸 것이라 전용 스크립트 4개를 씁니다.

```
extract_rosajeong.py    PDF → pipeline/casebook/rosajeong_cases.json  (원본 경로는 환경변수 ROSAJEONG_PDF)
rosajeong_ocr_fixes.py  OCR 오인식 교정표 — extract가 호출
reflow_rosajeong.py     조판 줄바꿈 되돌리기
parse_rosajeong.py      문제/최고답안/각주/배점 구조화
build_rosajeong_민사법.py  → data/민사법/ 에 병합
```

되돌릴 수 있게 만들어져 있습니다 — 몇 번을 다시 돌려도 기존 55건은 두고 `민사법_로사정_*`만
걷어낸 뒤 새로 붙입니다.

**OCR 교정이 이 작업의 핵심이었습니다.** 사례집에서 당사자 기호가 뒤바뀌면 답안이 무의미해지는데,
원본에는 `乙`이 **0회** 등장했습니다(2,073회 나오는 `甲`과 대비) — 전량 `江`·`己`로 오인식된 것입니다.
`丙`→`內`·`因`, `戊`→`成`, 로마자 `B`·`C`→`日`·`仁`도 같은 종류입니다.
잔여 의심 자리 395건은 전부 지면 이미지와 1:1 대조해 교정했고, 검증 결과는
`pipeline/casebook/rosajeong_verify.txt`에 0건으로 남아 있습니다 — **다시 0이 아니게 되면 새 문제가 생긴 것**입니다.

한글끼리의 오인식(예: `그!` ← `각`)은 자동으로 찾을 수 없습니다. 편집거리 1 후보는 한국어가 교착어라
정상 활용형끼리도 걸려 쓸 수 없고, 그나마 **희귀 음절 빈도**가 가장 잘 걸립니다(46만 음절 중 3회 이하인
156종만 훑으면 대부분 드러남). 남은 것을 다 잡으려면 632쪽을 사람이 읽는 수밖에 없습니다.
